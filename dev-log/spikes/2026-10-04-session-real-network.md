# Spike：連線迴圈 + PeerJS 實網換主機

- **日期**：2026-10-04
- **狀態**：🟡 通過，附一項已量化的限制（主機卡死時房間約 100 秒無法使用）
- **程式**：`dev-log/spikes/session-spike.html`（`js/net/session.js` + `js/net/transport-peer.js`，由 `window.T` 驅動）；ID 釋放量測用 `dev-log/spikes/peer-spike.html`

## 1. 要驗證的假設

1. jsDelivr `+esm` 版本提供具名匯出 `Peer`（peerjs）與 `z`（zod），import map 可直接用。
2. `session.js` 在真實 PeerJS 上：第一個分頁當主機，其他分頁加入；指令與狀態廣播正常。
3. 主機分頁關閉後，同一局由其他分頁接手；原主機重整後拿回座位。
4. 主機分頁卡死（JS 停止但連線未關）時，房間多久恢復。

## 2. 成功標準（事前訂定）

- [x] `typeof Peer === 'function'`、`typeof z === 'object'`
- [x] 三分頁全部上線，主機唯一
- [x] 擲骰後其他分頁收到新狀態
- [x] 關閉主機分頁後 5 秒內出現新主機，遊戲狀態（位置、現金、日誌序號）不變
- [x] 原主機重整後同一 id、同一座位、非主機
- [ ] 主機卡死後 30 秒內換主機：**未達成**，實測約 100 秒（見第 5 節）

## 3. 環境

Windows 11、Claude 內建瀏覽器（Chromium）、同一台機器 3 個分頁、peerjs@1.5.5 與 zod@4.6.5（jsDelivr `+esm`）、0.peerjs.com 公用信令、本機 `python -m http.server 5173`。

### 主機卡死（busy loop 75 秒）

| 時間（卡死起算） | 事件 |
|------|------|
| 10.1 s、11.1 s | 兩個客戶端心跳逾時，進入重連 |
| 10 到 75 s | 客戶端重試：搶 ID 回 `unavailable-id`，撥號 10 秒逾時，退避重試 |
| 75.0 s | 卡死結束；原主機自己的迴路也逾時，主機退位後重新搶 ID |
| 76.6 s | 原主機重新取得 ID，epoch 1 → 2，遊戲狀態不變 |
| 83.4 s、87.5 s | 兩個客戶端在下一輪重試時加入 |

### 信令伺服器多久釋放卡死分頁的 ID（busy loop 150 秒）

另一分頁每 3.5 秒嘗試註冊同一 ID：卡死後 0.6 到 98.4 秒共 29 次都是 `unavailable-id`，**101.9 秒成功**（卡死仍持續中）。
PeerJS 用戶端每 5 秒送一次信令心跳，因此伺服器約在最後一次心跳後 95 到 102 秒釋放 ID（樣本數 1）。

### 背景分頁計時器（文件證據，B 級）

Chrome 官方說明（developer.chrome.com/blog/timer-throttling-in-chrome-88）：隱藏頁面若有 `RTCPeerConnection` 且其 `RTCDataChannel` 為 open，只套用每秒一次的一般節流，不套用每分鐘一次的強化節流。
本專案的計時器（主機 tick 500 ms、心跳 2 秒、逾時 10 秒）在每秒對齊下仍能運作。只有主機與自己（無遠端連線）時沒有 DataChannel，但此時沒有人依賴它的心跳；新分頁連入後即有 DataChannel。

## 5. 結論

假設 1 到 3 通過。假設 4 未達標：主機 JS 停止但連線未關閉時（分頁卡死、手機切到背景被凍結、筆電闔上），0.peerjs.com 約 100 秒後才釋放 ID，這段期間沒有人能接手；
加上客戶端重試週期（最長 10 秒撥號逾時 + 5 秒退避），最壞約 115 秒恢復。正常關閉或重新整理分頁時只需約 0.6 秒。

**設計變更**：無。程式無法縮短信令伺服器的釋放時間；要更快需改用可設定 `alive_timeout` 的自架 PeerServer，或改為多 ID 備援（複雜度高，暫不做）。列入 GAPS G1。

## 6. 限制

1. 三分頁同機，WebRTC 走本機迴路；跨網路未測（GAPS G2）。
2. 無法模擬分頁程序崩潰（內建瀏覽器擋 `chrome://crash`）。崩潰時瀏覽器會關閉信令 WebSocket，預期行為與「關閉分頁」相同，未實測。
3. 100 秒為單一樣本；公用伺服器設定可能變動。

## 7. 過期條件

peerjs 升級、改用自架 PeerServer，或 0.peerjs.com 設定改變時重測第 4 節。
